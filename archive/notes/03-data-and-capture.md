# 数据集建设、核心集与补拍策略

## 两个“核心”要分开

历史**核心验证集 602 张**指保留下来的固定验证物理照片，用来监测旧能力。**核心补拍**指围绕重要失败模式主动采集新训练样本。补拍不会自动把核心验证图移进训练。

## 数据闭环

失败日志 → 确认错误发生层级 → 设计补拍场景 → 标注与复核 → 场景分组 → 训练重采样 → 同集评估 → 新场景实测 → 保留或回退。

先区分检测漏检、容量错分、桌面误归属、深度误杀、时序门槛和 OCR 区域漏选。只有外观模型的问题，才主要通过补拍与训练解决。

## 推荐补拍矩阵

| 维度 | 覆盖内容 | 避免的捷径 |
|---|---|---|
| 相机几何 | 近/中/远、不同俯角、桌面位置 | 只记住固定像素大小与桌子位置 |
| 光照和背景 | 现场地板、反光、阴影、背光 | 只在干净桌面上表现好 |
| 物品姿态 | 正面/背面、横放/直立、旋转角度 | 只依赖包装正面 |
| 遮挡 | 无遮挡、局部遮挡、相近类别共同出现 | 通过摆放记忆猜类别 |
| 背景同类物品 | 地面、桌后垫高、前侧堆叠 | 将“像物品”直接当成“在桌上” |
| 真假关系 | 贴图、真物、真物压住贴图 | 用邻物高度替贴图背书 |
| 容量对照 | 同品牌 350/550、不同品牌同容量 | 品牌/瓶盖颜色代替容量证据 |
| 小目标 | 眼镜、胶带、卷尺、遥控器的尺寸与角度 | 只补容易看清的大物品 |

每种布置拍一个短序列并记录场景 ID、相机距离、物品真值和变化因素。相邻曝光、旋转序列和同一摆放的多角度图应作为同组候选；启发式分组仍需抽查。

## 核心补拍的优先顺序

1. 针对固定错误，先补“单物品对照”：同品牌两种容量、眼镜正反角度、遥控器与相似外观。
2. 再补“少物品组合”：保持其他条件一致，只改变遮挡、姿态或桌边位置。
3. 最后补“现场复合场景”：真实背景、桌外堆叠、旋转、多个相似物品同时出现。
4. 单独封存一批新场景用于最终测试，避免在它上面反复调参后仍称独立测试。

## 标注与来源规则

- 类别顺序统一为 16 物品＋TABLE；标签别名规范化应留修订表。
- 矩形与多边形转框的规则固定；源 JSON 与派生训练标签分离。
- 看不清容量的瓶口不能仅凭拍摄者记忆或相对高度标容量；保留待复核状态。
- 未标注照片不能自动当“整图没有物品”的负样本。
- 桌外未标物品在全图检测训练中可能产生背景监督冲突。历史上受时间限制保留桌上精标，这是一项带代价的折中。
- 自动补标是人工复核起点。降低候选门槛只增加召回候选，不证明类别和边界正确。

## 数据污染防护

用物理原图 SHA 关联 JPG、遮罩 PNG、裁剪图等派生版本；不能因文件编码不同就把同一原图拆入训练和验证。完全重复图若标注冲突，先选定派生版本并保留审计记录。

AI 清理背景可能改变目标比例、位置、纹理和颜色。历史个案记录过约 1.4% 缩放和 5–8 像素位移。目标区域若要求不动，应使用确定性的原像素保留与坐标变换；合成背景的效果仍须在真实照片上验证。

## 采集表模板

`artifacts/capture-plan.csv` 提供可以直接填写的补拍表。每组至少记录：场景 ID、变化因素、真实物品与数量、桌外物品、是否遮挡、采集批次、用途与审核人。
