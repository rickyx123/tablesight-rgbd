# 模型选型、训练权重与采样迭代

## “改权重”包含三件不同的事

| 概念 | 项目中的含义 | 结果如何核验 |
|---|---|---|
| 网络权重 | `.pt` 中学习到的模型参数；由训练或微调更新 | checkpoint、参数规模、同集推理 |
| 样本权重 | 训练清单中某组图像重复出现，提高抽样频率 | 唯一图数、条目数、真实 loader 次数 |
| 置信度门槛 | 推理后筛选阈值，可能存在逐类覆盖 | 部署配置与固定阈值评估 |

历史 3/5/7/1 方案是**图像级重采样**，不是直接修改分类 loss，也不是手工修改某个神经元参数。同一图片中的全部类别同时增加抽样机会。

## 可追溯迭代

| 阶段 | 主要变化 | 已知边界 |
|---|---|---|
| 前期轻量版本 → m 级模型 | 2026-10-07 记录开始采用 YOLOv8m；保留旧包 | 旧架构的严格同集 A/B 待补，不将型号变化单独量化为收益 |
| V6m | 困难样本 3 倍，固定 602 核心验证图 | 新旧验证范围不同的训练截图不能直接比较 |
| V7m | 标签修订、旧水瓶遮罩、最后 500 张专项 3 倍、数据增加 | 多因素同时改变，不能当成采样单因素消融 |
| V8m | 从正式 V7 微调，新增现场数据，现场/旧专项/普通为 5/3/1 | 新现场提升，部分旧专项回退 |
| V9m | 从正式 V8 微调，新增现场批次，7/5/3/1 | 新 57 张验证参与过选模型；容量仍有弱项 |

V6–V9 已核验结构均为 YOLOv8m。V8、V9 约 2,586 万参数。文件名中的 V9 是内部版本，不是 YOLOv9 架构。

## 训练规模与真实抽样

| 版本 | 唯一训练图 | 唯一验证图 | 加权训练条目 | 采样策略 |
|---|---:|---:|---:|---|
| V6 | 2406 | 602 | 2642 | 专项 118 图 ×3，其余 ×1 |
| V7 | 2871 | 718 | 3667 | 专项 398 图 ×3，其余 ×1 |
| V8 | 3465 | 867 | 6637 | 现场 594×5，旧专项 398×3，普通 2473×1 |
| V9 | 3691 | 924 | 8219 | 新现场 226×7，昨日现场 594×5，旧专项 398×3，普通 2473×1 |

V9 各组单图优先级 7＞5＞3＞1，但每组总贡献还取决于图片数量。训练条目增加会影响每轮时间，不能只按唯一图片数估算训练成本。验证清单保持唯一。

## 为什么现场提升明显

实际现场照片补充了距离、地板、光照、包装和摆放分布；采样提高了这些样本在训练中的出现频率；从上一正式版本小学习率微调降低了重新学习成本。这些是与结果一致的解释，**目前没有单因素实验能分离每项贡献**。

已有记录支持“数据—模型迭代显著改善特定现场验证”，不支持“只调采样权重就提高某个固定数值”。

## 训练可靠性细节

- COCO 初始化的新基线，与从上一比赛权重微调，是不同实验。
- 短训仅做门禁，不把短训模型误当正式起点。
- 断点恢复需保留 optimizer、EMA、scaler、学习率与训练进度；已 strip 的 best 不是完整恢复点。
- AMP 使用当前权重和本地图像做离线数值检查，避免被自动下载校验模型阻塞。
- batch、workers 与显存利用率分别观察；大显存不自动等于高吞吐。
- 高权重组也可能被过拟合，必须同时检查现场集、旧专项和固定核心集。

`tablesight.sampling` 提供采样清单的可运行示例；它不能替代原始完整 AutoDL 训练包。
