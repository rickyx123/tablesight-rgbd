# 从“检测出物品”到“正确统计桌上物品”

[返回项目首页](../README.md) · [数据与模型](数据与模型.md) · [代码与运行](运行说明.md)

TableSight 的核心任务是识别并统计目标桌面上的实物。我们把问题分成四层：**认出类别 → 判断桌面归属 → 验证实物证据 → 合并跨帧实例**。错误发生在哪一层，决定了该补数据，还是修改几何和融合逻辑。

## 透视桌面：高度相近，不等于放在桌上

相机斜视方桌时，桌面呈梯形。矩形检测框包含桌外区域，桌后堆叠的物品又可能与桌面高度接近，导致薯片、方便面等背景物被统计进去。

实现中先用 TABLE 候选定位目标，再结合深度支撑与图像桌沿形成透视四边形。物品需要符合桌面区域归属，后沿也需要受到实际边界约束。重点不是一味缩小框，而是在过滤后方干扰的同时保留靠近桌边的真实物品。

后沿修改保留了七帧专项回放记录：这能验证该次场景的处理，尚不能证明所有视角都可靠。后续应系统覆盖远距离、不同俯角、遮挡后沿和桌后垫高物。

源码：[方桌边界](../reference/competition_snapshot/national_competition/runtime/square_surface.py) · [圆桌定位](../reference/competition_snapshot/national_competition/runtime/round_surface.py)

## 深度过滤：没有凸起和没有有效深度，需要分开

贴纸与实物的外观可能非常相似。深度是有价值的额外证据，但透明瓶、反光表面和遮挡会让深度缺失；邻近真物的高点也可能错误保护贴纸。

因此，深度判断保留三种状态：

| 状态 | 含义 | 决策考虑 |
|---|---|---|
| PASS | 存在可归属于候选物的立体证据 | 支持保留候选 |
| FLAT | 有足够可靠的平面证据 | 支持判为贴图 |
| UNKNOWN | 数据不足或证据冲突 | 避免直接当作贴纸删除 |

这部分的关键是证据能否归属于当前物体，而不只是框内有没有高点。阈值还需要考虑物品尺寸，薄小物品与大瓶子的合理尺度不同。历史日志中的深度残差也不能直接当成重力方向的真实高度。

源码：[深度验证](../reference/competition_snapshot/national_competition/runtime/depth_validation.py) · [深度归属](../reference/competition_snapshot/national_competition/runtime/depth_ownership.py)

## 旋转计数：视频中出现过，并不自动等于最终保留

圆桌旋转时，物体会改变位置和外观，同一个物体在不同角度下的置信度也不同。固定的最小出现帧数会让小物品吃亏；把所有检测框累加则会重复计数。

系统结合跨帧实例与有效桌面观测做汇总：桌面没有可靠定位的时刻，不应简单增加物品的缺席次数；多次出现的同一实例也不能重复增加数量。眼镜对视角特别敏感，因此后期放宽了它的双帧确认要求。

圆桌边界需要跟随实际观测更新，并限制异常膨胀。永久锁住首帧会在桌面移动或偏心旋转时失效，而过度放宽又会将地面物品带入。这是一项需要平衡连续性与当前证据的工程问题。

源码：[时序融合](../reference/competition_snapshot/national_competition/runtime/timed_fusion.py)

## OCR：文字识别与空间归属同样重要

语文、数学、洗洁精和沐浴露由文字标签定义。流程需要处理纸面区域、裁剪、文字匹配与候选物关系，而不是把“读出文字”直接等同于“可以计数”。圆桌上的跨帧排除还要绑定来源，避免某一帧的文字位置错误删除另一帧的物品。

比赛参考快照保留了已确认版本；曾尝试但取消的全图 OCR 兜底没有作为参赛成果纳入。

源码：[OCR 识别](../reference/competition_snapshot/national_competition/runtime/ocr_worker.py) · [排除逻辑](../reference/competition_snapshot/national_competition/runtime/ocr_exclusivity.py)

## 实机落地：每一层都要能追查

检测、深度验证和 OCR 的计算预算不同。NPU 运行模型，CPU 负责几何、融合及文字任务；异步结果必须对应原来的图像序号，避免用后一帧的深度判断前一帧的物品。

模型导出还需要核对类别顺序、预处理、后处理和实际加载版本。现场调试保留逐帧记录与结果归档，才能区分模型漏检、桌面筛选、深度误删和计票不足。

第一轮连接失败时仍可本地识别并保存；第二轮缺少通信时可保留首桌结果，但不能假定云台已经完成后续转向。相机启动失败也需要与“检测后没有物品”分开记录。
